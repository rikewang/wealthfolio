# Wealthfolio 功能与代码收口计划

记录日期：2026-11-01（Asia/Shanghai）

状态：规划阶段。本次仅记录范围、执行顺序和验收条件；尚未隐藏页面、停用能力、删除代码或修改运行中的服务。

相关文档：[需求差距与演进计划](requirements-and-roadmap.md)、[部署与接入说明](../README.md)。

## 1. 决策与目标

采用“**先收起入口并阻止非必要初始化 → 验证核心流程 → 停用不需要的能力 → 按依赖逐步删代码**”的顺序。

先把产品收敛为个人资产与投资分析工具，保留资产总览、持仓、洞察、活动流水、AI 助手，以及必要设置。宏观观察、关注列表和研究功能仍按原路线逐步增加，未实现前不摆放空入口。

隐藏入口、停用功能、删除代码、清理数据是四种不同操作：

- **隐藏入口**：减少导航和页面干扰，保留实现和历史数据，可快速恢复。
- **停用功能**：不启动对应查询、会话、后台任务或工具调用；需要核对服务端和原生端的执行边界。
- **删除代码**：删除已经确定不用、依赖清楚且通过回归验证的实现。隐藏并不意味着将来一定要删除。
- **清理数据**：单独处理，不与删代码捆绑。本计划不删除任何目标、预算、流水、账户、资产、贷款记录或历史数据库结构。

隐藏不是权限控制。仅从菜单移除，不能证明旧链接、API、AI 工具或后台逻辑已停用。

1. `dashboard-content.tsx`

## 4. 分阶段执行与架构影响

### 阶段 A：入口收敛，保留实现和数据

- 建立明确的精简展示策略，并同步作用于侧边栏、移动导航、设置、首页卡片、搜索和快捷操作。
- 隐藏组件应不挂载其专属查询 hooks，避免仅用 CSS 隐藏仍然发生请求。
- 对
  `/goals`、消费与供款限额等旧链接提供一致的未启用说明或安全跳转；在路由保护之前不执行功能页面的查询。
- 深链接中的 `tab=spending` 等参数需要回退到有效页签，避免空白页和跳转循环。
- 不更改用户的目标、预算、行情提供商或 AI 权限设置。涉及 Connect 的网络停用沿用其既有禁用路径，并安排阶段 C 的服务端验证。

**Architecture
impact**：第一轮主要改变 UI 可见性、路由可达性以及专属组件发起的查询；不修改账户 / 交易存储、估值算法、数据源映射、导入导出格式或数据库 schema。隐藏状态本身不作为 API 安全边界。

### 阶段 B：独立环境验收与回退演练

- 用现有示例数据建立本机隔离验收环境；使用不同的 Compose 项目名、端口和数据目录。
- 核对资产、负债、现金、持仓数量、交易数、目标和预算记录；行情自然变化导致的估值差异，与账本变更分开判断。
- 验证精简与恢复显示均可用，个人档案和示例档案数据保持原样。
- 至少覆盖一次完整的登录、查看组合、行情更新、导出和重启流程，再讨论删代码；不以“页面没报错”作为唯一通过标准。

**Architecture
impact**：此阶段不向外发送新增个人财务数据；验证报告与备份保存在忽略的本地目录。演示数据不提交到仓库，不在真实档案中重跑生成脚本。

### 阶段 C：停用不需要的能力

- 明确每项能力的“不可见”和“不可执行”状态；保留高级配置的功能不等同于已停用。
- 对 Connect 复用已有前端禁用 context、平台能力和服务端构建 feature，核对会话恢复、轮询、同步及 OAuth 回调是否仍会执行。
- 对明确停用的目标 / 供款 / 消费专属功能，按实际需求核对 API、AI 工具、原生命令与后台任务；默认 UI 不应触发它们，执行限制必须由对应服务端或原生端落实。
- 不关闭共享的档案登录、加密存储、报价同步、分类和账务服务；不把普通行情刷新与 Connect 同步混为一谈。
- 不清除已有凭据或同步状态来模拟停用，保留恢复原配置的可能。

**Architecture
impact**：此阶段可能改变服务端 / 原生端功能可用性、工具注册及后台网络行为。每个具体实现任务都要列出影响接口、错误行为、配置优先级和验证方法；不能把这一阶段称为单纯的界面重构。

### 阶段 D：逐模块删除专属代码

只有符合第 5 节门槛的模块才能进入此阶段。建议分开提交，顺序为：

1. 确定不用的专属页面、组件、导航项及静态资源。
2. 已无消费者的专属 hooks、前端适配调用和类型。
3. 对应的工具注册、Web API、Tauri 命令和专属服务，逐项核对两种运行方式。
4. 确认没有共享引用后的依赖、资源和翻译键，并更新所有受影响语言与测试。

供款限额的专属入口优先评估；目标、消费与贷款模块存在共享数据和计算，需更谨慎。Connect 优先保持关闭，只有持续维护成本确实需要时再做依赖级删除。MCP、插件扩展和备用行情提供商不列为首批删除对象。

**Architecture
impact**：删代码会改变可用接口、包依赖与构建产物。旧数据结构及已发布迁移保留；不通过删除迁移文件或数据库表来实现代码精简。数据清理另立任务，并单独设计兼容与恢复方案。

## 5. 删除门槛

每个模块需要同时满足：

1. 已确认不属于近期资产管理、行情观察、研究或 AI 集成需求。
2. 入口隐藏和能力停用已经验收，恢复显示与回退也已验证。
3. 导航、路由、搜索、首页卡片、导入导出、后台任务、AI 工具及插件调用均完成消费者检查。
4. 共享日期、金额、分类、账户、现金流、估值和备份逻辑有明确归属，不随专属功能删除。
5. 新旧数据读取、核心账务结果和 Web /
   Tauri 调用关系不被破坏；不删除历史记录来让检查通过。
6. 删除范围能够独立提交和回滚，并与上游合并的维护成本比较后确有收益。

无法满足这些条件时，保留代码但保持停用。首轮隐藏后不自动进入大规模删代码。

## 6. 验收清单

### 展示与访问

- 桌面、移动导航、设置、搜索、首页卡片采用一致的功能范围。
- 旧链接、书签、刷新和浏览器前后退不会打开被隐藏的业务页或产生空白页。
- 核心入口可发现，AKShare、Yahoo、AI、账户、导出、备份和健康检查仍可使用。
- 右到左布局和所有受影响语言保持可用。

### 数据与执行

- 已有 9 个示例账户、464 条模拟流水、持仓数量及原有目标 / 预算等记录保留；以实施前新采集的本地基线为准，不能覆盖用户之后新增的数据。
- 个人档案与示例档案隔离保持不变，资产负债和现金 / 持仓可核对。
- 国内 12 个标的、海外资产与汇率能继续更新，数据日期和计价单位正确。
- AI 的核心账户和组合查询继续可用；明确停用的功能不能通过默认工具入口被重新执行。
- 验证停用逻辑没有非必要初始化或网络调用；前端菜单隐藏不被当成后端拒绝调用的证明。

### 按实际变更执行检查

- 仅改文档：检查引用、格式和 diff，本次采用此范围。
- 前端显示 / 路由：相关单次 Vitest、lint、`pnpm type-check`；变动 UI 文案时补齐翻译并跑
  `pnpm --filter frontend i18n:check`。
- 构建或运行方式配置：按仓库要求验证 `pnpm build` 与 `pnpm build:tauri`。
- API / 原生命令或工具注册：补充
  `adapter-command-parity.test.ts`、相关服务端与原生端测试和编译。
- Rust 业务或持久化：相关 crate 测试、格式、Clippy 及受影响运行时编译。
- 页面验收按 `AGENTS.md`、`.claude/skills/run-e2e-tests/SKILL.md` 和
  `e2e/README.md` 执行适用的定向测试；净资产或插件沙箱发生变化时，补跑对应套件。

## 7. 构建、发布与回滚

当前部署使用官方固定镜像。仅修改 fork 中的前端代码不会改变 `localhost:8088`
的界面。

实施时需从明确的 fork 提交构建独立镜像，以提交标识记录版本；验证使用隔离数据目录，确认构建上下文没有密钥或数据库。完成验收后，再在具体部署任务中替换运行镜像。

阶段 A 的回退恢复显示策略；阶段 C 的回退恢复原能力配置；阶段 D 的回退使用独立提交和上一镜像。上述阶段都保留原数据库结构，避免把代码回退与不可逆的数据清理绑定。

每批实施前记录当前版本、配置及本地账本基线；备份在本地受保护目录保存。密码、密钥、数据库、缓存、备份和验收报告继续排除在 Git 之外。
