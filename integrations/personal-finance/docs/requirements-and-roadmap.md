# 个人财富与投资研究工具：需求差距与演进计划

记录日期：2026-11-01（Asia/Shanghai）

评估基线：本地 Wealthfolio 3.11.0、AKShare 1.20.2 行情服务、已接通的 Magpie /
OpenAI 助手。

状态：产品需求和候选方案记录。本文不代表已实现下列待办，也不触发功能删除、推送或自动交易。

## 1. 产品目标与边界

建设一个可逐步扩展的个人财富管理与投资研究工具，主要覆盖：

1. **资产梳理**：资产、负债、持仓、成本、现金流和组合收益。账户只作为资产来源标签，不收集券商密码或交易凭据。
2. **观察与策略**：宏观指标、股票及产业数据、基金、黄金、量化盯盘、策略条件、风险提示和消息推送。
3. **AI 研究**：整理关注博主的内容，保留原始依据，拆解观点，查找支持证据与反例，关联关注标的并持续验证。
4. **后续交易能力**：先研究、提醒和模拟验证；自动交易放到后期独立设计。

第一阶段使用简单可用的版本，逐步扩展数据和功能。保留现有演示数据用于验收，与个人真实资产档案隔离。

## 2. 已有能力及适合保留的部分

Wealthfolio 适合作为资产账本和组合分析基础：

- 资产、负债、持仓、成本与多币种汇总。
- 交易及现金流水、分红利息、收益表现和历史估值。
- 行业与资产类别分类、配置偏离分析、再平衡计划。
- 手动录入、CSV 导入导出、备份、登录保护和本地加密数据库。
- 通过自定义行情源接入国内价格数据，通过 AI 工具查询账本。

“账户”保留为来源标签；“流水”支撑成本和收益计算；“分类”和“配置目标”支撑集中度与偏离观察。这些属于基础能力，不宜因为界面复杂而删除。

### 当前接入验证范围

- 国内行情实际调用 AKShare，已有 12 个国内标的验证通过，覆盖 A 股、场内 ETF、场外公募基金和上金所 Au99.99。
- A 股 / ETF 使用未复权日收盘价，基金使用正式单位净值，Au99.99 使用人民币 / 克。
- 股票 /
  ETF 的适配器历史保留最近 640 根已完成日线；基金与黄金取上游实际返回，原样本向 Wealthfolio 写入最近约 5 年历史。
- Wealthfolio 当前映射只使用收盘价；适配器保留可用 OHLC，成交量尚未输出。不能把页面默认的 OHLC 或 0 成交量用于量价策略。
- Yahoo 保留用于已配置的海外证券、BTC 和汇率。国内行情不依赖 Connect。
- 当前没有无人值守的每日观察任务、策略推送或券商自动交易。
- 示例包含 9 个账户、16 个投资标的和 464 条模拟流水；实际公开价格配合虚构的数量、成本、现金流及规划假设，仅用于演示，不能作为真实策略回测成绩。

| A 股、基金和黄金数据 | 日线与净值已接通                 | 扩大品种覆盖；交易日历、分红拆股、数据异常检测及来源记录                                              | P0               |

| 独立关注列表         | 能登记尚未持有的证券             | 关注理由、研究标签、触发条件、观察状态、研究资料关联；关注不要求创建持仓                              | P0               |

| 提醒与推送           | 尚未配置                         | 阈值触发、重复提醒抑制、恢复通知、失败重试、投递记录；先选飞书或邮件，微信另行确认可用通道            | P0               |

| A 股风险观察         | 有组合和数据健康检查             | 公告、ST、减持、质押、异常量价、龙虎榜、两融等观察；既有健康检查主要检查账本问题                      | P1               |
| 基金研究             | 有净值与收益曲线                 | 持仓穿透、持仓重叠、风格变化、经理变更、费率、申赎限制及披露日期                                      | P1               |
| 自动交易             | 未接入                           | 券商接口、订单状态、风控、成交对账、故障停止和明确授权                                                | P2               |

补充边界：

- 接通 AKShare 只完成了部分数据入口。宏观指标、财报、产业关系和研究材料仍需适合各自结构的存储与分析界面。
- 宏观收益率、产业指标等不应强行当作可持仓证券价格保存。
- 组合历史表现、退休情景模拟与交易策略回测是不同用途，不能混用结果。
- 风险观察用于提示需要核查的信息，不承诺识别所有风险；估值条件应考虑行业、盈利和历史背景，不设一个通用的“安全 PE”。
- 每个数据项需保留单位、币种、频率、来源、观察日期和更新时间；财报、基金披露等还应保留公布时间，防止回测使用当时尚不可得的信息。

## 4. 当前可以精简的功能

以下属于相对于本阶段需求的低优先级项。优先隐藏入口、收进高级设置或简化演示，不删除既有数据。

| 功能                            | 建议         | 原因与保留边界                                               |
| ------------------------------- | ------------ | ------------------------------------------------------------ |
| 供款限额                        | 隐藏入口     | 主要面向 IRA、401(k)、TFSA 等账户，当前未提出对应需求        |
| 详细消费预算、旅行事件          | 暂缓         | 先保留总现金流；逐笔消费管理不是本阶段重点                   |
| 复杂退休 / FIRE 模拟            | 降低优先级   | 属于长期财务规划，先建设投资观察闭环                         |
| 大量储蓄目标                    | 精简默认展示 | 教育、旅行、换车等是演示假设，不应直接成为个人档案的默认任务 |
| Connect、券商自动导入、家庭共享 | 当前保持关闭 | 当前没有对应需求；AKShare 行情不依赖 Connect                 |
| 未使用的海外数据源配置          | 收进高级设置 | 主界面突出 AKShare 与已使用的 Yahoo，降低配置负担            |
| 复杂贷款推演、过细消费分类      | 暂缓         | 保留资产总额、负债余额和现金流，按需求再扩展                 |

**继续保留**：账户标签、投资流水、资产分类、配置目标、房产和负债汇总、导入导出、备份和数据健康检查。

目标页面主要承载储蓄与退休规划；投资策略的观察条件应有独立位置。储蓄目标可以弱化，但资产配置目标仍有实际用途。

## 5. AI 与隐私边界

当前 AI 助手通过本机 Magpie 调用 OpenAI，已验证可调用 `get_accounts`
等账本工具。其主要已接通能力是查询和解释账本，尚未建立博主采集、联网证据研究和持续观察流程。

本地数据库存储与 AI 推理的数据流需要分别说明：对话、附件及工具返回的相关资产信息可能发送给云端模型。本地部署不能等同于 AI 完全本地运行。

后续应利用既有权限机制，按任务明确数据范围并验证：

- 公共市场与博主研究默认不读取个人账户、持仓数量或成本。
- 组合分析按需要读取已授权的数据，可按任务使用汇总或脱敏结果。
- 研究、提醒、账本写入、交易执行分开授权，保留必要操作记录。
- 券商凭据和交易权限不进入当前公开行情与研究服务。

本记录不改变现有 AI 提供商配置或数据访问权限。

## 6. 建议的建设顺序与验收标准

### 第一阶段：关注列表与宏观看板

- 独立记录关注标的、指标、理由、标签和数据来源，不要求创建持仓。
- 集中展示优先关注的汇率、美债收益率、指数、黄金及 BTC。
- 验收：观察项可新增和分组；单位、来源和数据日期清晰；缺失、过期及失败状态可见。

### 第二阶段：每日更新、规则提醒与消息投递

- 建立稳定的每日调度，先支持少量可解释规则。
- 每次触发记录条件、观测值、时间与来源；有去重、重试和投递记录。
- 先接一个明确选定的飞书或邮件通道，微信通道另行验证。
- 验收：任务不依赖页面保持打开；满足条件能提醒；同一事件不反复轰炸；数据故障不会被误报为交易信号。

### 第三阶段：研究资料库与 AI 分析

- 连接“博主观点 → 原文与时间 → 支持证据和反例 → 关联标的 → 后续验证”。
- 区分原文事实、作者观点、模型推断与待核查事项，保留引用。
- 逐步加入财报、产业关系、基金持仓与 A 股风险观察。
- 验收：能追溯结论来源，能把研究关联到关注项，能按后续数据记录观点是否成立。

### 第四阶段：策略回测和模拟运行

- 建立独立策略与信号记录，补齐数据口径、费用、滑点和可交易约束。
- 先历史验证，再持续模拟；观察信号在真实更新时间与数据延迟下的表现。
- 自动交易在此后另立任务，设计券商接入、风控和故障停止机制。

## 7. 扩展方式

建议保留 Wealthfolio 的资产账本和组合分析能力，将观察、研究、规则和推送放到独立服务，复用现有行情接口，并通过明确接口读取必要的组合信息。界面可以整合到同一入口，避免为了扩展研究数据而大幅改写核心账本。

Wealthfolio 的自定义数据源和可选 MCP / Agent
Access 可作为集成接口；是否启用、开放哪些读写能力需按实际任务配置。本文不启用这些新增权限。
